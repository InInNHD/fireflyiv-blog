服务器每天 03:30 会备份 Docker 数据卷、Beszel 数据、博客内容、Nginx 与 systemd 配置，并保留七天。但“定时任务成功”只证明文件被写出，不证明它们能恢复。

## 先按数据类型分类

- Markdown、Compose 和 Nginx 配置适合进入 Git，负责重建服务形态；
- SQLite 应在应用停止或使用在线备份 API 时复制，避免只拿到主库却遗漏 WAL；
- Postgres 使用逻辑导出，恢复时校验表数量和关键查询；
- 上传文件与应用数据库必须一起恢复，否则记录和文件会失去对应关系；
- 密钥只进入权限为 `600` 的离线密码表或密钥系统，不写进仓库和备份日志。

## 一次恢复演练该检查什么

在临时目录或隔离容器中解压最新备份，启动应用后依次验证登录页、数据条数、随机附件、公开 API 和反向代理。然后记录恢复耗时，以及哪些步骤仍然依赖手工记忆。

恢复演练还应抽查更老的一份备份。只验证“最新包”可能错过静默损坏或轮转脚本的问题。真正有意义的指标不是备份文件大小，而是最近一次成功恢复的时间和步骤。

当前体系仍缺少异地副本。下一步会把加密后的归档同步到对象存储，并保留本地七天轮转；在异地化完成前，服务器磁盘故障仍是明确的单点风险。
